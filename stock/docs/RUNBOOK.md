# RUNBOOK — ระบบ Stock อะไหล่

คู่มือคนดูแลระบบ · อ่านตอนระบบมีปัญหา ไม่ใช่ตอนติดตั้ง
ติดตั้งครั้งแรกดู [SETUP.md](SETUP.md) · สอนใช้งานดู [HOWTO.md](HOWTO.md)

## 1. ข้อมูลอยู่ไหน

**ทุกอย่างอยู่ในชีต ไม่ได้อยู่ในโค้ด** — โค้ดพังทั้งหมด เปิดชีตทำงานต่อด้วยมือได้ทันที
นี่คือเหตุผลที่เลือก Google Sheets ตั้งแต่แรก

| ชีต | เป็นอะไร |
|---|---|
| `Parts` | ทะเบียนอะไหล่ — **ไม่มีคอลัมน์คงเหลือ** |
| `Batches_FIFO` | **ของจริงอยู่ที่นี่** · คงเหลือ = `SUM(Qty_Left)` ของอะไหล่ตัวนั้น |
| `Stock_Moves` | บันทึกการเคลื่อนไหวทุกครั้ง — หลักฐาน ห้ามแก้ |
| `Ref_Log` | กันการบันทึกซ้ำเวลาเน็ตหลุดแล้วกดซ้ำ |
| `Tools` · `Blades` | เครื่องมือช่าง · ใบมีด |
| `Users` | บัญชีและ PIN — แชร์กับระบบ CMMS ถ้าใช้คู่กัน |
| `Settings` | ค่าระบบ แก้ได้โดยไม่ต้องแตะโค้ด |

> ⚠️ **ห้ามพิมพ์ตัวเลขทับในชีต `Batches_FIFO` หรือ `Stock_Moves`**
> ยอดต้องขยับผ่านหน้าจอเท่านั้น ไม่งั้นหลักฐานกับของจริงไม่ตรงกันโดยไม่มีใครรู้
> ชีตหลักฐานถูกล็อกไว้แล้ว ถ้าปลดล็อกเองต้องรู้ว่ากำลังทำอะไรอยู่

## 2. ขึ้นเวอร์ชันใหม่ (deploy)

```bash
node tests/run.js
```

ต้องได้ **`ผ่านครบทุกชุด`** ถ้าไม่ผ่าน **หยุด** อย่า deploy

```bash
clasp push -f
```

ตอนนี้โค้ดขึ้นไปแล้ว **แต่คนใช้ยังเห็นเวอร์ชันเดิม** เพราะลิงก์ `/exec` ปักหมุดอยู่ที่เวอร์ชันที่ deploy ไว้

**Deploy › Manage deployments › ✏️ แก้ไข › Version: New version › Deploy**

> นี่คือสาเหตุอันดับหนึ่งของอาการ "แก้โค้ดแล้วหน้าเว็บไม่เปลี่ยน"
> บันทึกไฟล์ไม่ใช่การ deploy · `clasp push` ก็ยังไม่ใช่

ถ้าใช้ clasp ทั้งหมด:

```bash
clasp deployments                      # ดูรหัส deployment ที่คนใช้อยู่
clasp deploy -i <DEPLOYMENT_ID> -d "1.2.0 — อธิบายสั้น ๆ"
```

เสร็จแล้วเปิดหน้าเว็บ เบิกของทดสอบหนึ่งใบ แล้วยกเลิก — พิสูจน์ว่าเส้นทางเขียนยังทำงาน

---

## 3. ย้อนกลับเมื่อ deploy แล้วพัง

**ย้อนก่อน หาสาเหตุทีหลัง** — ให้คนทำงานต่อได้เป็นอันดับแรก

**Deploy › Manage deployments › ✏️ › Version: เลือกเวอร์ชันเก่าที่ยังดีอยู่ › Deploy**

หรือ

```bash
clasp versions                                  # ดูว่ามีเวอร์ชันอะไรให้ย้อน
clasp deploy -i <DEPLOYMENT_ID> -V <เลขเวอร์ชัน>
```

ใช้เวลาไม่ถึงนาที **ไม่ต้องแก้โค้ดก่อน**

> ข้อมูลในชีตไม่ย้อนตาม — การย้อนเวอร์ชันแก้ได้แค่โค้ด
> ถ้าเวอร์ชันที่พังเขียนข้อมูลผิดลงชีตไปแล้ว ต้องไปแก้ที่ชีตแยกต่างหาก

## 4. งานอัตโนมัติ

| เวลา | ฟังก์ชัน | ทำอะไร |
|---|---|---|
| 08:00 ทุกวัน | `dailyAlert` | เมลเตือน: ของถึงจุดสั่งซื้อ · batch ใกล้/เลยวันหมดอายุ · รหัสซ้ำ · พื้นที่เก็บข้อมูลใกล้เต็ม |

**ถ้าเมลหยุดส่ง** — เปิดตัวแก้ไข เลือก `installTriggers` แล้ว Run
ฟังก์ชันนี้ลบ trigger เก่าแล้วสร้างใหม่ รันซ้ำได้ไม่สะสม

> ต้องล็อกอินเป็น `ENG` ก่อน ไม่งั้นจะโดนปฏิเสธ
> trigger หายได้เมื่อเปลี่ยนเจ้าของโปรเจค หรือสิทธิ์หมดอายุ

**เมลไปไหน** — ตั้งที่ชีต `Settings` ช่อง `ALERT_EMAILS` ไม่ต้องแก้โค้ด

ดูว่ารันสำเร็จไหม: ตัวแก้ไข → เมนูซ้าย **Executions**

## 5. ฟังก์ชันที่รันเองจากเมนู

เลือกจากรายการด้านบนตัวแก้ไข แล้วกด **Run** · ผลออกที่ **Execution log**

| ฟังก์ชัน | ใช้เมื่อไหร่ |
|---|---|
| `clearCatalogCache` | **หลังแก้ชีต `Parts` / `Settings` ด้วยมือ** — ไม่รันแล้วหน้าจอยังเห็นของเก่า |
| `installTriggers` | เมลเตือนรายวันหยุดทำงาน |
| `setup` | สร้างชีตที่ขาด · รันซ้ำได้ ไม่เขียนทับชีตที่มีข้อมูลแล้ว |
| `emergencyResetPin` | **วิศวกรเข้าระบบไม่ได้ทุกคน** — ดูข้อ 7 |
| `backupAndTrim` | ชีตบันทึกยาวจนช้า — ดูข้อ 8 |

## 6. งานที่ทำบ่อย

### เพิ่มอะไหล่ใหม่
ทำในแอป หน้า "ออกรหัสใหม่" — ระบบออกรหัส 17 ตัวให้เอง
**อย่าพิมพ์รหัสเองในชีต** รหัสซ้ำแล้วรายงานจะนับแยกเป็นสองตัว

### แก้ Min / Max / ที่เก็บ
แก้ในแอป หรือแก้ในชีต `Parts` แล้วรัน `clearCatalogCache`

### ยอดในระบบไม่ตรงกับของบนชั้น
ใช้หน้า **นับสต๊อก** ในแอป — มันปรับที่ batch และลงบันทึกให้
**ห้ามแก้ตัวเลขในชีตเอง** จะได้ยอดตรงแต่ไม่มีหลักฐานว่าใครปรับ เมื่อไหร่ เพราะอะไร

### เพิ่มผู้ใช้
ชีต `Users` → เพิ่มแถว → ตั้ง PIN ให้เขาในแอป (เมนูผู้ดูแล) หรือให้เขาตั้งเองตอนล็อกอินครั้งแรก

> ใช้ชีต `Users` ร่วมกับ CMMS อยู่หรือเปล่า → อ่าน [SHARED-USERS.md](../../SHARED-USERS.md) ก่อนแตะคอลัมน์

## 7. ลืม PIN / เข้าระบบไม่ได้

**กรณีปกติ** — คนที่เป็น `ENG` ตั้ง PIN ใหม่ให้ได้จากในแอป

**กรณีฉุกเฉิน — `ENG` เข้าไม่ได้ทุกคน**

1. เปิดตัวแก้ไข Apps Script → ไฟล์ `Auth.gs`
2. หาฟังก์ชัน `emergencyResetPin` แก้อีเมลและ PIN ชั่วคราวในโค้ด
3. เลือก `emergencyResetPin` → **Run**
4. เข้าระบบด้วย PIN นั้น **แล้วเปลี่ยนทันที**
5. **ลบ PIN ชั่วคราวออกจากโค้ด** แล้ว push ใหม่ — ไม่งั้นมันค้างอยู่ในซอร์สให้ใครก็อ่านได้

> ป้องกันไว้ดีกว่า: **ตั้ง `ENG` ไว้อย่างน้อย 2 คน** ไม่มีแอดมินภายนอกมากู้ให้

## 8. ชีตโตจนช้า

Google Sheets จำกัด **10 ล้านเซลล์ต่อไฟล์** — ชนเมื่อไหร่ **เขียนไม่ได้ทั้งไฟล์**
ไม่ใช่แค่ช้า คือเบิกของไม่ได้เลย

เมลรายวันเตือนล่วงหน้าเมื่อพื้นที่ใกล้เต็ม

**ตัดข้อมูลเก่า** — เลือก `backupAndTrim` แล้วแก้พารามิเตอร์ในโค้ดเป็นชื่อชีตกับจำนวนวันที่จะเก็บ

```
backupAndTrim('Stock_Moves', 365)
```

มัน **เขียน CSV ลง Drive ก่อน แล้วค่อยลบแถว** และตัดได้เฉพาะชีตบันทึกย้อนหลังเท่านั้น
ไฟล์สำรองอยู่ในโฟลเดอร์ `สำรองข้อมูล - <ชื่อชีต>`

> เก็บขั้นต่ำ 30 วันเสมอ ระบบไม่ยอมให้ตัดสั้นกว่านั้น

## 9. อาการเสียที่เจอบ่อย

| อาการ | สาเหตุที่เจอจริง | แก้ |
|---|---|---|
| แก้โค้ดแล้วหน้าเว็บไม่เปลี่ยน | ยังใช้ deployment เวอร์ชันเดิม | ข้อ 2 |
| แก้ชีตแล้วหน้าจอไม่เปลี่ยน | แคชรายการอะไหล่ | `clearCatalogCache` |
| เบิกแล้วได้สองใบ | เน็ตหลุดแล้วกดซ้ำ | ระบบกันด้วย `Ref_Log` อยู่แล้ว · ถ้ายังเจอ ให้เช็คว่าชีต `Ref_Log` ถูกลบไปหรือเปล่า |
| กล้องสแกนไม่ขึ้น | เว็บแอปอยู่ใน iframe ที่บางเบราว์เซอร์บล็อกกล้อง โดยเฉพาะในแอป LINE | ใช้ปุ่มถ่ายรูปแทน (`capture`) ที่มีสำรองไว้ · หรือเปิดใน Chrome ตรง ๆ |
| ยอดคงเหลือดูแปลก | มีคนพิมพ์ทับใน `Batches_FIFO` | ดู `Stock_Moves` หาว่าหลักฐานหายช่วงไหน |
| `Exceeded maximum execution time` | งานเกิน 6 นาที | รันซ้ำ · งานหนักควรแบ่งเป็นช่วง |
| ทุกอย่างเขียนไม่ได้พร้อมกัน | ชีตชน 10 ล้านเซลล์ | ข้อ 8 |

อยู่ใน **Project Settings › Script Properties** เท่านั้น · **ห้ามเก็บในชีต `Settings`** ที่คนทั้งแผนกเปิดได้

## 11. สำรองข้อมูล

ยังไม่มีระบบอัตโนมัติ **ทำด้วยมืออย่างน้อยเดือนละครั้ง**

1. เปิดไฟล์ชีต → File › Make a copy → ตั้งชื่อ `Stock backup YYYY-MM`
2. เก็บในโฟลเดอร์ของบริษัท ไม่ใช่ไดรฟ์ส่วนตัว

`backupAndTrim` เขียน CSV ให้อยู่แล้วตอนตัดข้อมูล แต่นั่นคือของที่ถูกตัดออก ไม่ใช่ภาพรวมทั้งคลัง

## 12. ความเสี่ยงที่ยังไม่ได้ปิด

| เรื่อง | ทำไมสำคัญ |
|---|---|
| **โปรเจคอยู่ใต้บัญชีคนเดียว** | บัญชีนั้นถูกปิด = เว็บแอปดับ · trigger หยุด · ไม่มีใคร deploy ได้ → ย้ายไปบัญชีบริษัทและตั้งผู้ดูแลคนที่สอง |
| เขียนหลายชีตไม่ใช่ transaction | ล็อกกันคนชนกันได้ แต่กันไฟดับกลางคันไม่ได้ · ตายระหว่างตัด batch กับลง `Stock_Moves` = ของหายจากคลังโดยไม่มีบันทึก |
| ไม่มี staging | ทดสอบของจริงต้องทำบนระบบจริง · ใช้ deployment แยกสำหรับทดสอบไปก่อน |
