# ระบบ Stock อะไหล่ — การติดตั้ง

> **ถ้าจะตั้งระบบตั้งแต่ศูนย์ให้จบ 100% อ่าน [HOWTO.md](HOWTO.md)** — คู่มือทีละคลิก พร้อมเช็คลิสต์
> ไฟล์นี้เป็นเอกสารอ้างอิง: โครงตาราง กฎที่ฝังใน backend ระบบกันพลาด และข้อจำกัด

สแตกเดียวกับโปรเจค POS: Google Sheets (ฐานข้อมูล) + Apps Script (backend) + Tailwind CDN (หน้าจอ) — ฟรีทั้งหมด

| ไฟล์ในโฟลเดอร์นี้ | ชื่อใน Apps Script | คืออะไร |
|---|---|---|

| [Auth.gs](../src/Auth.gs) | `Auth.gs` (Script) | PIN, session, ประตู API เดียว |

## 1. สร้างโปรเจค

1. เปิดสเปรดชีตที่จะใช้เป็นฐานข้อมูล → **ส่วนขยาย → Apps Script**
2. วาง [Code.gs](../src/Code.gs) ทับ `Code.gs` เดิม
3. **+ → Script** ชื่อ `Auth` วาง [Auth.gs](../src/Auth.gs)
4. **+ → Script** ชื่อ `Data` วาง [Data.gs](../src/Data.gs) — ข้อมูลตั้งต้นทั้งคลัง (~187 KB)
5. **+ → HTML** สามครั้ง ชื่อ `Index`, `App.js`, `Admin.js` วางไฟล์ให้ตรงกัน
6. Ctrl+S — รวมหกไฟล์

## 2. สร้างตาราง

เลือก `setup` ใน dropdown → **Run** → อนุญาตสิทธิ์
(*ขั้นสูง → ไปที่… (ไม่ปลอดภัย)* → อนุญาต — เป็นสคริปต์ของคุณเอง)

`setup()` **ไม่ลบอะไรทั้งนั้น**: ชีตที่มีอยู่แล้วจะถูกเติมเฉพาะคอลัมน์ที่ยังขาด และคอลัมน์เดิมไม่ถูกแตะ

**`setup()` ลงข้อมูลจริงให้เลย** (อะไหล่ 997 · เครื่องมือ 94 · ใบมีด 145) เขียนเฉพาะชีตที่ยังว่าง
จึงรันซ้ำได้โดยไม่ทับของจริง · ยอดคงเหลือแยกไปที่ `seedOpeningStock()` ให้กดเอง
เพราะเป็นยอดของวันที่ export ไม่ใช่ของวันนี้
**ใส่บาร์โค้ดจริงลงคอลัมน์ Part_No** — นั่นคือสิ่งที่เครื่องสแกนเทียบ

คงเหลือ *ไม่เคย* เป็นคอลัมน์ในตาราง `Parts` — ยอดคงเหลือคือ `SUM(Qty_Remaining)` ของ batch ตัวนั้นเสมอ
การตัดสินใจข้อเดียวนี้คือสิ่งที่ทำให้ FIFO, ต้นทุนต่อเครื่องจักร, การคืนของ และการนับสต๊อก ถูกต้องได้ทั้งหมด

## 3. ข้อมูลเดิม

`setup()` ลงให้แล้วจาก [Data.gs](../src/Data.gs) — ไม่ต้องก๊อปวาง CSV
อะไหล่ **997** · เครื่องมือ **94** · ใบมีด **145** คัดซ้ำออกแล้ว (เหลือรหัสซ้ำ 0 รายการ)

**ยอดคงเหลือแยกต่างหาก** — รัน `seedOpeningStock()` ใน Apps Script ถ้าจะใช้ยอดจากชีตเดิม
(570 รายการ เข้าเป็น batch เดียว `GRN-OPENING`) หรือนับของจริงแล้วรับเข้าเองที่หน้า **รับเข้า & สั่งซื้อ**
ทำได้ครั้งเดียวตอนคลังยังว่างเท่านั้น — กันยอดยกมาถูกใส่ซ้ำจนสต๊อกเบิ้ล

อยากแก้ข้อมูลตั้งต้น: แก้ในชีตเอาเลย ง่ายกว่าแก้ใน `Data.gs`
รายละเอียดการ map ทุกคอลัมน์: [MIGRATION.md](MIGRATION.md)

## 5. รหัสและสิทธิ์ — PIN ต่อคน

หน้าเว็บเปิดมาที่หน้าล็อก ทุกแถวในชีต `Users` คือหนึ่งบัญชี

| สิทธิ์ | ทำอะไรได้ |
|---|---|
| **TECH — ช่าง** | สแกนเบิกอะไหล่เอง · คืนของที่ตัวเองเบิก · ดูคลัง คงเหลือ บัตรสต๊อก · ใบเบิกของตัวเอง · ติดตั้ง/ถอด/ส่งลับคมใบมีด · ดูทะเบียนเครื่องมือ |
| **LEAD — หัวหน้าช่าง** | ทุกอย่างของช่าง + รับเข้า · สั่งซื้อ · นับสต๊อก · ตัดจำหน่าย · แก้ข้อมูลอะไหล่/เครื่องมือ/ใบมีด · รายงาน · เห็นต้นทุน · จ่ายของแทนคนอื่น |
| **ENG — วิศวกรปฏิบัติการ** | ทุกอย่าง + ผู้ใช้และสิทธิ์ · ตั้งค่า · ประวัติการแก้ไข · ปลดระวางใบมีด · เก็บกวาดข้อมูล |

ทีมนี้ไม่มีแอดมินภายนอกคอยมอนิเตอร์ ระบบจึงออกแบบให้ดูแลตัวเองได้:
**แผง "สุขภาพระบบ"** ในหน้ารายงานบอกสิ่งที่ค้างอยู่ (รหัสซ้ำ · อะไหล่ที่ยังไม่ตั้ง Min ·
ถึงจุดสั่งซื้อ · ของหมดอายุ · ของนอน) และเรื่องเดียวกันถูกส่งเป็นอีเมลทุกเช้า 08:00
ส่วนกรณีที่ `ENG` เข้าไม่ได้ทุกคน มี `emergencyResetPin()` ใน [Auth.gs](../src/Auth.gs) เป็นทางออก —
รันจาก Apps Script editor เท่านั้น เรียกจากเบราว์เซอร์ไม่ได้

**ช่างแก้ข้อมูลไม่ได้เลย** และไม่ใช่แค่ซ่อนปุ่ม — ทุก endpoint ที่เขียนข้อมูลเช็ค `requireRole_('LEAD')`
ที่ฝั่งเซิร์ฟเวอร์ ยิงตรงจาก DevTools ก็ไม่ผ่าน

**ผู้เบิกถูกระบุจากบัญชีที่เข้าระบบ** ช่างส่งชื่อคนอื่นมาก็ถูกเขียนทับด้วยชื่อตัวเอง
เจ้าหน้าที่คลังพิมพ์ชื่อคนที่มารับของได้ (จ่ายแทน) และระบบยังบันทึกแยกว่าใครเป็นคนคีย์ —
คอลัมน์ `Requester` = คนรับของ, `User` = บัญชีที่ทำรายการ

- PIN ถูก **salt + SHA-256 hash** — ชีตไม่เคยเก็บ PIN ที่อ่านได้ และสองคอลัมน์นั้นถูกซ่อน
- **ใส่ผิด 5 ครั้งล็อก 15 นาที** และการล็อกถูกบันทึกลง audit log
- session อยู่ **12 ชั่วโมง** (หนึ่งกะ) เก็บในเบราว์เซอร์นั้น ออกจากระบบแล้วหมดทันที
- ทุกคำขอผ่าน **ประตูเดียว** (`call()` ใน [Auth.gs](../src/Auth.gs)) ที่ตรวจ session แล้วส่งต่อตามชื่อจาก allowlist
  ฟังก์ชัน helper (ชื่อลงท้าย `_`) เรียกจากเบราว์เซอร์ไม่ได้เลย

> **ทำทันทีหลัง deploy:** ตั้งค่า → ผู้ใช้และสิทธิ์ → ตั้ง PIN ให้ทุกบัญชี
> บัญชีที่ยังไม่มี PIN ใครที่รู้อีเมลนั้นยึดได้ตอนเข้าครั้งแรก — หน้าตั้งค่าจะเตือนไว้ให้

`SHOW_COST_TO_TECH = 0` (ค่าเริ่มต้น) ช่างจะไม่เห็นต้นทุนและมูลค่าสต๊อก — ตัดออกที่เซิร์ฟเวอร์
(`maskCost_()`) ตัวเลขที่ไม่ได้ส่งออกไป อ่านจาก DevTools ไม่ได้

## 6. ใช้งานครั้งแรก ตามลำดับนี้

1. **ตั้งค่า** — ชื่อคลัง, บังคับเลขใบแจ้งซ่อมหรือไม่, เครื่องจักร, ผู้ใช้ + PIN
2. **คลังอะไหล่** — `+ เพิ่มอะไหล่` ทีละตัว (หรือคีย์ลงชีต `Parts`) ตั้ง **Min / Max** ให้ครบ ไม่งั้นระบบเตือนของใกล้หมดไม่ได้
3. **รับเข้า & สั่งซื้อ** — รับยอดยกมา/ของเข้าใหม่: ผู้ขาย, รหัส, จำนวน, ต้นทุน, (วันหมดอายุถ้ามี) → **รับเข้าคลัง**
4. **เบิกอะไหล่** — ช่างสแกน, ระบุเครื่องจักร, **ยืนยันการเบิก**, พิมพ์ใบเบิกไปเซ็น
5. **นับสต๊อก** ทุกเดือน · **รายงาน** ดูต้นทุนอะไหล่ต่อเครื่องจักรและของนอน

## 7. กฎที่ฝังอยู่ใน backend

- **หมดอายุก่อนออกก่อน (FEFO) แล้วจึงเข้าก่อนออกก่อน (FIFO)** — อะไหล่ส่วนใหญ่ไม่มีวันหมดอายุก็จะเป็น FIFO ล้วน
  จาระบี น้ำมัน ยางซีล ที่กรอกวันหมดอายุไว้จะถูกหยิบก่อน
- **ของหมดอายุเบิกไปใช้ไม่ได้** ระบบจะบอกให้ตัดจำหน่ายก่อน — แต่การนับสต๊อกและตัดจำหน่ายหยิบมันได้
- **ต้นทุนคิดฝั่งเซิร์ฟเวอร์เสมอ** เบราว์เซอร์ส่งมาแค่รหัสอะไหล่ จำนวน และปลายทาง
- **`LockService` ครอบทุกการเขียน** — สองแท็บเล็ตเบิก batch เดียวกันเกินของที่มีไม่ได้
- **ตรวจครบก่อนเขียน** — ใบเบิกที่มีบรรทัดใดของไม่พอ จะไม่เขียนอะไรลงชีตเลย
- **คืนของกลับเข้า `Batch_ID` เดิม** ที่มันออกไป (ไล่จาก batch ที่หยิบท้ายสุด) ต้นทุนจึงไม่เพี้ยน
- เสนอสั่งซื้อ = เติมขึ้นไปถึง `Max_Qty` (ไม่ตั้ง Max ใช้ `2 × Min_Qty`) แล้ว**ปัดขึ้นเป็นจำนวนเท่าของ `MOQ`**
  — ผู้ขายที่ขายยกกล่อง 25 ตัว ต้องการ 2 ก็สั่ง 25 (`reorderQty_()`)
- ทุกการเคลื่อนไหวลง `Stock_Moves` · ทุกการแก้ค่าที่ไม่มีร่องรอยอื่นลง `Audit_Logs`
- **รหัสอะไหล่ออกตามมาตรฐาน Code SP V1** 17 ตัว และเลขลำดับถูกจองใน `lock_()` เดียวกับที่เขียนแถว
- **ใบมีด**: เปลี่ยนสถานะได้ทางเดียวคือ `bladeAction()` — จำนวนวันคำนวณจากวันติดตั้ง ไม่ให้คนกรอก
  และหนึ่งตำแหน่งติดตั้งมีใบมีดได้ใบเดียว
- **แท็กบาร์โค้ด**: วาดด้วย JsBarcode / qrcodejs ไม่วาดลายเอง (ลาย Code128 ที่ผิดหนึ่งเส้น
  = สติกเกอร์ทั้งแผ่นที่สแกนไม่ออก) · ตัวอย่างบนจอใช้ CSS ก้อนเดียวกับตอนพิมพ์ จึงโกหกไม่ได้
  · โลโก้ฝังเป็น data URI ในโค้ด ไม่พึ่งไฟล์หรือลิงก์ที่พังได้
- **กันคีย์ซ้ำ**: เบิก/รับเข้า/ตัดจำหน่าย ส่งรหัสอ้างอิงหนึ่งค่าต่อหนึ่งฟอร์ม กดซ้ำเพราะเน็ตหลุด
  จะได้เลขเอกสารเดิมกลับไป ไม่ตัดสต๊อกรอบสอง · รับบิลเลขเดิมซ้ำต้องยืนยันก่อน ·
  รหัสอะไหล่ซ้ำในชีตถูกจับและเตือน (รายละเอียดทั้งหมด: [HOWTO.md §14](HOWTO.md))

## 8. เทส

รัน `runAllTests` ใน editor (ดู Execution log → `ALL TESTS OK`) เป็นเทสในหน่วยความจำ ไม่แตะชีต:

- `testFifo_` — ลำดับ FEFO/FIFO, กระจายข้าม batch, ต้นทุน, ปฏิเสธการเบิกเกิน, ไม่แก้ค่าเมื่อ throw, ของหมดอายุ
- `testReturn_` — คืนเข้า batch เดิมโดยย้อนจาก pick ล่าสุด, อ่าน/เขียน batch label, batch ที่หายไป
- `testAudit_` — การเทียบค่า: `"45"` กับ `45` ไม่ใช่การเปลี่ยน, วันเทียบเป็นวัน
- `testArchive_` — batch ไหนย้ายออกได้ batch ไหนต้องเก็บไว้เพื่อรองรับการคืนของ
- `testDupes_` — จับรหัสอะไหล่ซ้ำ รวมถึงที่ต่างแค่ตัวพิมพ์ใหญ่เล็กและช่องว่าง
- `testReorder_` — จำนวนสั่งซื้อ: เติมถึง Max, ไม่มี Max ใช้ 2 × Min, ปัดขึ้นตาม MOQ, ไม่เคยสั่ง 0 หรือติดลบ
- `testPartCode_` — ประกอบ/แยกรหัส 17 ตัวด้วยตัวอย่างจริงจากไฟล์มาตรฐาน และ Running นับต่อ Code name
- `testBlade_` — การนับวัน (ข้ามเดือน/ปี, วันเดียวกัน = 0, วันย้อนหลังไม่ติดลบ, ช่วง 250 วันจากข้อมูลจริง)
- `testAuth_` — PIN salt + hash, token ไม่ซ้ำ, ประตูปฏิเสธคำสั่งที่ไม่รู้จักและ token ปลอม, **ช่างผ่านด่าน STORE ไม่ได้**

## 9. ข้อจำกัดที่รู้อยู่

- `getCatalog()` cache ไว้ 5 นาทีใน `CacheService` และทุกการเขียนล้างมันผ่าน `lock_()` หน้าเบิกจึงไม่เคยเห็นของที่ไม่มีอยู่
  catalog ที่เกิน ~90 KB จะไม่ถูก cache (CacheService ปฏิเสธค่าเกิน 100 KB) — อ่านสดทุกครั้ง ช้ากว่าแต่ถูกต้องเสมอ
  เก็บ `Batches_FIFO` ให้ผอมด้วยปุ่มย้าย batch ในแท็บตั้งค่า
- session เก็บใน Script Properties ซึ่งเป็นของสคริปต์ ไม่ใช่ของ user — พอสำหรับคลังเดียว
- ไม่มีโหมดออฟไลน์ ต้องมีเน็ต · เน็ตหลุดกลางการเบิก = ไม่มีอะไรถูกเขียน
- เบราว์เซอร์ส่ง byte ตรงเข้าเครื่องพิมพ์ไม่ได้ ใบเบิกจึงพิมพ์ผ่าน driver ของ OS เป็น HTML กว้าง 58/80 มม.
- โควตา Apps Script: ~20k การเรียกสเปรดชีตต่อวันในบัญชีฟรี — พอสำหรับคลังเดียว

## ที่ยังไม่ได้ทำ (ตั้งใจข้าม)

| ไม่มี | เพิ่มเมื่อ |
|---|---|
| ระบบอนุมัติก่อนเบิก | เบิกของแพงต้องให้หัวหน้าอนุมัติก่อน — เพิ่มสถานะ `PENDING` ใน `Issues` |
| พิมพ์สติกเกอร์บาร์โค้ดติดชั้นวาง | ของที่มาแบบไม่มีบาร์โค้ดเริ่มเยอะ (ยกโค้ด JsBarcode จากโปรเจค POS มาได้ตรง ๆ) |

| หลายคลัง / หลายโซน | มีคลังย่อยแยกอาคาร — ตอนนี้ `Location` เป็นข้อความบอกชั้น/ช่องเท่านั้น |
| สลับไทย/อังกฤษ | มีคนใช้ที่อ่านไทยไม่ได้ (ยกดิกชันนารี `TH` + MutationObserver จากโปรเจค POS มาได้) |
| เก็บกู้ตะกร้าเวลาแท็บเล็ตดับ | ตะกร้าเบิกสามบรรทัด คีย์ใหม่เร็วกว่าดูแลโค้ดกู้คืน |
| ผูกกับระบบแจ้งซ่อม/สถานะเครื่องจักร | ตอนนี้ผูกด้วยข้อความ: `Job_No` + `Machine` ตรงกันก็ VLOOKUP ข้ามชีตได้เลย |
| ชั่วโมงเดินเครื่องจริงสำหรับใบมีด | ต้องดึงจากระบบสถานะเครื่องจักร — ตอนนี้นับเป็นวันตามข้อมูลเดิม |
| ยืม-คืนเครื่องมือเป็นรายครั้ง | ตอนนี้เป็นทะเบียน "อยู่กับใคร" ตามของเดิม ถ้าต้องยืม-คืนรายวันค่อยเพิ่ม log แบบใบมีด |
