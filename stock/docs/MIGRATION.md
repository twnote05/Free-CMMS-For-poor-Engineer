# ย้ายข้อมูลเดิม + มาตรฐานรหัส Code SP V1

อ่านจากสองแหล่ง แล้วเทียบกับสูตรในไฟล์เอง — ตรงกันทุกแถว:
`โครงสร้างสำหรับกำหนดรหัส.xlsx` (954 แถว, มาตรฐานการออกรหัส) และ
แท็บจริงจาก Google Sheet `Spare Part All` — `อะไหล่สต็อก` (1,012 รหัส) · `อะไหล่สินเปลือง` ·
`เครื่องมือช่าง` · `ใบมีด`

## 1. โครงรหัส 17 ตัว (ถอดจากสูตรในไฟล์)

```
6      00      01      001      M001      -      0001
│      │       │       │        │                │
│      │       │       │        │                └ Running       4 หลัก
│      │       │       │        └ Code name      4 ตัว (อักษรย่อหมวดชนิด)
│      │       │       └ Sub group 1             3 หลัก (เลขหมวดชนิด)
│      │       └ Type                            2 หลัก
│      └ การใช้งาน                                2 หลัก
└ Item Group Main                                1 หลัก
```

สูตรเดิมในไฟล์: `TEXT(A,"0") & TEXT(G,"00") & TEXT(B,"00") & TEXT(D,"000") & F & "-" & TEXT(H,"0000")`
ตรวจกับข้อมูลจริง: **598 แถวที่รหัสครบ ประกอบกลับได้ตรงทุกแถว · รหัสซ้ำ 0 รายการ**

| ส่วน | ค่าที่ใช้ได้ | ที่มา |
|---|---|---|
| Item Group Main | 1 วัตถุดิบ · 2 SM · 3 FG · 5 สิ้นเปลือง · **6 อะไหล่** | legend A1 |
| การใช้งาน | 00, 01 (ยังไม่กำหนดความหมายในไฟล์) | legend F1 + ข้อมูลจริง |
| Type | 01 electronic · 02 Machanic · 03 Calibration · 04 สิ้นเปลือง | legend B1 + ชีต Type |
| Sub group 1 + Code name | 73 หมวด (000 E-Clip/E001 … 072 Contactor/C010) | ชีต เลือกหมวดชนิด |
| Running | 0001–9979 | คำนวณ |

### Running นับต่อ Code name ทั้งระบบ — ไม่ใช่ต่อ prefix

จุดนี้สำคัญที่สุดและเดาผิดง่ายที่สุด ยืนยันจากข้อมูลจริง:

- `M001` วิ่ง 0001–0019 **ต่อเนื่อง** แม้อยู่คนละการใช้งาน (`60001001M001-…` และ `60101001M001-…`)
- มี 8 Code name ที่ถูกใช้ข้าม Type/การใช้งาน — ถ้านับ Running แยกต่อ prefix **จะออกรหัสชนกันทันที**
- ทดสอบทั้ง 74 Code name และ 81 prefix: ไม่มี Running ซ้ำเลยทั้งสองแบบ แต่แบบต่อ Code name เข้มกว่า
- ระบบจึงใช้ `MAX(Running ของ code4 นั้น) + 1` เหมือนสูตรเดิมเป๊ะ **และไม่ถมรูที่ว่าง**
  (`T006` มี 35 แถวแต่เลขสูงสุด 0040 → ตัวถัดไปคือ 0041 ไม่ใช่เลขในรู) เพราะรหัสที่เคยออกไป
  อยู่บนเอกสารและสติกเกอร์แล้ว การเอากลับมาใช้ใหม่คือการชนกันแบบเงียบ ๆ

### แถวที่เอาอักษรย่อเครื่องจักรไปใส่ช่อง Code name

ข้อมูลเดิมมีสองธรรมเนียมปนกัน — บางแถวใส่อักษรย่อหมวด (`B004`, `T006`) บางแถวใส่อักษรย่อเครื่อง
(`MIX1`, `MIX2`, `CM01`) เช่น `60002022MIX2-0001` ระบบ**ข้ามแถวพวกนี้ตอนหา Running อัตโนมัติ**
เพราะ code4 ไม่ตรงกับหมวดที่เลือก — เหมือนที่สูตรเดิมกัน `CM01` ไว้ รหัสเดิมยังใช้งาน/เบิกได้ปกติ
แค่ไม่ถูกนับเข้าลำดับของหมวด

## 2. ตัวสร้างรหัสในระบบ

**คลังอะไหล่ → + เพิ่มอะไหล่** จะมีกล่อง "ออกรหัสตามมาตรฐาน Code SP V1" อยู่บนสุด:
เลือก 4 ช่อง → เห็นรหัสที่จะได้ทันที → กรอกชื่อ → บันทึก

- ลิสต์ทั้งสี่ชุดอยู่ในชีต **`Code_Master`** (`List | Key | Label_EN | Label_TH | Code4`)
  เพิ่มหมวดใหม่ = เพิ่มแถว `CATEGORY` พร้อมเลข 3 หลักและอักษรย่อ 4 ตัวที่ยังไม่มีใครใช้ — ไม่ต้องแตะโค้ด
- **เลขจริงถูกจองตอนกดบันทึก ไม่ใช่ตอน preview** และจองอยู่ใน `lock_()` เดียวกับที่เขียนแถว
  สองคนกดเพิ่มอะไหล่หมวดเดียวกันพร้อมกันจึงไม่ได้ Running เดียวกัน
  (ถ้าค้างหน้าจอไว้นานแล้วเลขถูกคนอื่นใช้ไป ระบบออกเลขใหม่ให้ตอนบันทึกและแจ้งรหัสที่ได้จริง)
- พิมพ์รหัสเดิมหรือบาร์โค้ดผู้ผลิตทับลงไปได้ ระบบไม่บังคับให้ทุกตัวเข้าโครง
- เปิดอะไหล่เดิมมาแก้ ระบบถอดรหัสให้อ่านว่าเป็นหมวดอะไร ลำดับที่เท่าไร

### วิธีวาง (ทำตามลำดับ)

## 4. การ map คอลัมน์ และสิ่งที่ต้องตัดสินใจ

### อะไหล่

| แท็บเดิม | ลงคอลัมน์ | หมายเหตุ |
|---|---|---|
| รหัสสินค้า | `Part_No` | ตรง |
| ชื่อรายการ (คอลัมน์ B) | `Name` | ตรง |
| — | `Category` | **ถอดจากรหัสให้** 269 แถว (จากอักษรย่อ 4 ตัว) ที่เหลือใส่ `อะไหล่`/`สิ้นเปลือง` ไว้ก่อน |
| Location | `Location` | 613 แถว |
| ตำแหน่งใช้งาน | `Position` | 472 แถว — คอลัมน์ที่เพิ่มให้ใหม่ เพื่อไม่ให้ข้อมูลนี้ตกหล่น |

| **MOQ** | **`Min_Qty`** | **ดูคำอธิบายด้านล่าง** |
| เครื่องจักร | `Machine` | แปลงชื่อเต็มเป็นอักษรย่อให้ ("Mixer 1 106 KW" → `MIX1`) |
| คงเหลือ | → ไฟล์ยอดยกมา | สต๊อกเข้าระบบทางการรับเข้าเท่านั้น |
| รูปอะไหล่ | *ยังว่าง* | รูปใน Sheets เป็นวัตถุลอย ไม่ได้อยู่ในเซลล์ จึง export ไม่ติด — วางลิงก์รูปในคอลัมน์ `Image` ได้ทีหลัง |
| Status (⚠️) / PR / นับจริง | *ไม่ใส่* | ⚠️ 314 แถวคือ flag งานเอกสาร ซึ่งระบบใหม่คิดจาก Min เองแล้ว |

**เรื่อง MOQ ที่ต้องเข้าใจให้ตรงกัน** — คอลัมน์ `MOQ` เดิมถูกใช้เป็น *"จำนวนที่ต้องมีอย่างน้อย"*
(ตรวจแล้วต่างจากยอดคงเหลือ 374 แถว จึงเป็นค่าที่ตั้งใจกรอก) ระบบใหม่แยกสองเรื่องนี้:

| คอลัมน์ | ความหมาย | ใช้ทำอะไร |
|---|---|---|
| `Min_Qty` | ต่ำกว่านี้คือต้องสั่ง | **ขึ้นเตือน** + ดึงเข้าใบสั่งซื้อ |
| `MOQ` | ขั้นต่ำที่ผู้ขายรับต่อครั้ง | **ปัดจำนวนที่สั่งขึ้น** ให้ครบขั้นต่ำ |

จึง map `MOQ` เดิม → `Min_Qty` (740 แถว) และปล่อย `MOQ` ใหม่ว่างไว้
ถ้าเข้าใจผิด สลับสองคอลัมน์ใน CSV ได้เลย

**ยังว่างทั้งหมด:** `Max_Qty` (ระบบใช้ `2 × Min` แทน) · `Supplier` · `Cost`
— สามช่องนี้ไม่มีในแท็บเดิมเลย ถ้ามีไฟล์ราคา/ผู้ขายแยกอยู่ ส่งมาเติมให้ได้

### เครื่องมือช่าง

แท็บเดิมเป็น 5 ตารางวางเรียงข้างกัน (ช่างซ่อมบำรุง / Slot / Ext / UV / Xpe) ระบบรวมเป็นตารางเดียว
แล้วใช้คอลัมน์ `Team` แยกทีม — จึงค้นข้ามทีมได้ และนับของทั้งโรงงานได้ในทีเดียว

| แท็บเดิม | ลงคอลัมน์ |
|---|---|
| หัวตารางแต่ละบล็อก | `Team` |
| รายการเครื่องมือช่าง | `Name` |
| จำนวน / หน่วย | `Qty` / `Unit` |
| ผู้รับผิดชอบ | `Holder` |
| วันที่รับมอบ | `Handover_Date` |
| ราคา | `Price` |
| — | `Tool_ID` = `TL0001`… ระบบออกให้ |
| คำว่า "หาย" / "ชำรุด" ที่เขียนต่อท้ายชื่อ | `Status` (สูญหาย 5 · ชำรุด 1) |

**ข้อสังเกต:** เดิมสถานะถูกเขียนปนในชื่อรายการ ("ค้อนด้ามไฟเบอร์ หาย") ซึ่งค้นและนับไม่ได้
ระบบแยกเป็นคอลัมน์ `Status` ให้ — **ชื่อยังมีคำเดิมติดอยู่** ลบออกได้ตามสะดวก

### ใบมีด

## 5. 89 แถวที่ยังใช้ไม่ได้

เปิด `Parts_needs_fixing.csv` — เป็นแถวที่ไม่มีรหัส (เขียนว่า `ยังไม่เปิดรหัส` 6 แถว) ไม่มีชื่อรายการ
หรือรหัสซ้ำกับแถวก่อนหน้า (7 รหัส)

สองทางเลือก:
1. **ทิ้งไว้ก่อน** เอา 997 แถวที่ครบเข้าระบบแล้วใช้งานจริงได้เลย ตัวที่ขาดค่อยกด
   **+ เพิ่มอะไหล่** ให้ระบบออกรหัสใหม่ตามมาตรฐานตอนมีของเข้า
2. **เติมชื่อ/รหัสในไฟล์แล้วส่งกลับมา** จะรวมเข้าไฟล์ import ให้

**รหัสซ้ำ 7 รหัสต้องแก้แน่ ๆ** (ไฟล์ import ตัดตัวที่ซ้ำออกให้แล้ว แต่ของจริงมีสองแถว) —
ถ้าเป็นของสองตัวที่ต่างกันจริง ต้องออกรหัสใหม่ให้ตัวหนึ่ง

## 6. ข้อมูลเดิมที่ยัง "ผิดโครงสร้าง" — ไม่ต้องรีบแก้

ในแท็บจริง 1,012 รหัส:

| กลุ่ม | จำนวน | ระบบทำอะไร |
|---|---|---|
| เข้าโครง Code SP V1 ครบ 17 ตัว | 576 | ใช้งานเต็มรูปแบบ ถอดหมวดได้ นับ Running ต่อได้ |
| เอาอักษรย่อ**เครื่องจักร**ไปใส่ช่อง Code name (`EXT1` `CM01` `MIX2` …) | 302 | ใช้เบิก/นับ/รายงานได้ปกติ แต่ **ไม่ถูกนับเข้าลำดับของหมวด** |
| รหัสรูปแบบเก่า (`MTD3MI1-021`) | 436 | ใช้งานได้ปกติ ระบบไม่บังคับให้ทุกตัวเข้าโครง |

**ไม่ต้องแก้ย้อนหลัง** — รหัสที่ออกไปแล้วอยู่บนสติกเกอร์และเอกสาร การเปลี่ยนรหัสเก่า
คือการทำให้ของบนชั้นกับในระบบไม่ตรงกัน ระบบจึงรับทั้งสามแบบ และ**ออกรหัสใหม่ให้ถูกมาตรฐานตั้งแต่ตัวถัดไป**
