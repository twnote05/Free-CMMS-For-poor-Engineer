## 1. ระบบนี้ประกอบด้วยอะไร

```
Google Form เช็คชีตประจำวัน           ─┐
Google Form พารามิเตอร์              ─┤  ← ช่างกรอกที่นี่
หน้าเว็บแจ้งซ่อม (ฝ่ายผลิต)            ─┘
                                        ▼
                Google Sheets (ข้อมูลทั้งหมดอยู่ที่นี่)
                                        ▼
                Apps Script Web App → หน้าจอ 10 แท็บ
```

**ข้อมูลอยู่ในชีต ไม่ได้อยู่ในโค้ด** — ถ้าโค้ดพังทั้งหมด ข้อมูลยังอยู่ครบ
เปิดชีตแล้วทำงานด้วยมือต่อได้ทันที นี่คือเหตุผลที่เลือก Google Sheets

## 3. ขั้นตอนขึ้นระบบ (deploy)

```bash
node test.js
```

ต้องได้ `OK — ผ่านทั้งหมด` ถ้าไม่ผ่าน **หยุด** อย่า deploy

```bash
npx clasp push -f
```

ตอนนี้โค้ดขึ้นไปอยู่บน Apps Script แล้ว แต่ **ช่างยังใช้เวอร์ชันเดิมอยู่**
เพราะ `/exec` ชี้ไปที่เวอร์ชันที่ปักหมุดไว้ ไม่ใช่โค้ดล่าสุด

ทดสอบก่อนจริงได้ที่ deployment `@HEAD` ซึ่งชี้ไปที่โค้ดล่าสุดเสมอ

เมื่อมั่นใจแล้วจึงปล่อยให้ช่างเห็น:

```bash
npx clasp deploy -i <DEPLOYMENT_ID> -d "1.4.8 — คำอธิบายสั้นๆ"
```

> ⚠️ `-i` ต้องเป็นรหัสนี้เสมอ — มันคือลิงก์ที่ช่างบุ๊กมาร์กไว้
> ถ้าสร้าง deployment ใหม่ ลิงก์จะเปลี่ยน แล้วทุกคนเข้าไม่ได้

จากนั้นเปิดตัวแก้ไข Apps Script → เลือก `clearCache` → Run

### ตรวจว่าขึ้นจริง

```bash
npx clasp deployments
```

บรรทัดที่ขึ้นต้นด้วย `<DEPLOYMENT_ID>` ต้องแสดงเลขเวอร์ชันใหม่

## 4. ย้อนกลับเมื่อ deploy แล้วพัง

ชี้ลิงก์เดิมกลับไปที่เวอร์ชันที่ยังดีอยู่:

```bash
npx clasp deploy -i <DEPLOYMENT_ID> -V 57
```

ใช้เวลาไม่ถึงนาที **ไม่ต้องแก้โค้ดก่อน** — ย้อนให้คนทำงานต่อได้ก่อน แล้วค่อยหาสาเหตุ

ดูว่ามีเวอร์ชันอะไรให้ย้อนบ้าง:

```bash
npx clasp versions
```

ดึงโค้ดของเวอร์ชันหนึ่งมาดู:

```bash
npx clasp pull --versionNumber 57
```

## 5. งานอัตโนมัติ (triggers)

| เวลา | ฟังก์ชัน | ทำอะไร |
|---|---|---|
| 06:00 | `extendPmSchedule` | ต่อตาราง PM ล่วงหน้า |
| 07:00 | `dailyDigest` | ส่งสรุปงานค้างให้หัวหน้า |
| 08:00 | `nudgeAssignees` | เตือนช่างที่มีงานค้างเกินกำหนด |

**ถ้า trigger หาย** (เกิดขึ้นได้เมื่อเปลี่ยนเจ้าของโปรเจคหรือ token หมดอายุ):
เปิดตัวแก้ไข → เลือก `setupTriggers` → Run · ฟังก์ชันนี้ลบของเก่าแล้วสร้างใหม่ รันซ้ำได้ไม่เสียหาย

ดูว่า trigger รันสำเร็จหรือไม่: ตัวแก้ไข → เมนูซ้าย **Executions**

## 6. ฟังก์ชันที่รันเองจากเมนู (ไม่มีผลข้างเคียง)

เลือกจากรายการฟังก์ชันด้านบนตัวแก้ไข แล้วกด Run · ผลออกที่ **Execution log**

| ฟังก์ชัน | ใช้เมื่อไหร่ |
|---|---|
| `clearCache()` | **หลัง deploy ทุกครั้ง** และหลังแก้ชีต `ตั้งค่า` / `Users` / `ทะเบียนเครื่องจักร` — ไม่รันจะเห็นข้อมูลเก่าไปอีก 5 นาที |
| `dataIssues()` | ตรวจคุณภาพข้อมูลทั้งระบบ — เครื่องไม่มีผู้ดูแล ช่องเช็คลิสต์ไม่มีชื่อ ค่าพิกัดน่าสงสัย ใบที่เวลาไม่สมเหตุสมผล รหัสผ่านอ่อน · **อ่านอย่างเดียว ไม่แก้อะไร** |
| `sourceAudit()` | ตรวจว่าไฟล์พารามิเตอร์/เช็คชีตที่ผูกไว้เปิดได้ และชื่อเครื่องผูกทะเบียนติดไหม |
| `techAudit()` | ดูว่าช่อง "ผู้เข้าซ่อม" มีชื่อกี่แบบ แบบไหนยังไม่รู้จัก |
| `setup()` | สร้างชีตที่ขาด — รันซ้ำได้ ไม่ลบข้อมูลเดิม |
| `setupTriggers()` | สร้างงานอัตโนมัติใหม่ |

## 7. งานที่ทำบ่อย

### เพิ่มเครื่องจักรใหม่
ชีต `ทะเบียนเครื่องจักร` → เพิ่มแถว → กรอก `ชื่อเครื่องจักร`, `รหัสเครื่อง`, `ประเภท`, **`ผู้ดูแล`** → รัน `clearCache()`

> `ผู้ดูแล` ต้องสะกดตรงกับช่อง `สถานีประจำ` ในชีต `Users` เป๊ะ ๆ: `EXT` · `UV` · `CUT` — อะไรก็ได้ที่คุณใช้จริง`
> สะกดไม่ตรง = ไม่มีช่างคนไหนเห็นเครื่องนั้นในโหมด "เครื่องของฉัน" และ**ไม่มี error บอก** · `dataIssues()` จับให้

### ชื่อเครื่องในฟอร์มไม่ตรงกับทะเบียน
อย่าแก้ชื่อในทะเบียน — ใส่ชื่อที่ฟอร์มใช้ลงช่อง `ชื่อเดิมที่เคยใช้` (คั่นหลายชื่อด้วย `,`) แล้วรัน `clearCache()`

### เพิ่มผู้ใช้
ชีต `Users` → เพิ่มแถว → `อีเมล`, `ชื่อ-นามสกุล`, `บทบาท` (`TECH`/`ENG`/`LEAD`/`ADMIN`), `ใช้งาน` = TRUE, `สถานีประจำ`

> **ห้ามสลับลำดับคอลัมน์ 1-9** — ระบบ Stock อะไหล่อ่านตามตำแหน่ง ไม่ใช่ตามชื่อ · สลับแล้วระบบนั้นพังทันที · ดู [SHARED-USERS.md](../../SHARED-USERS.md)
> คอลัมน์ที่ 10 ขึ้นไปเพิ่มต่อท้ายได้ตามสบาย

### รีเซ็ต PIN
ชีต `Users` → ลบค่าในช่อง `PIN` และ `SALT` ของคนนั้น → ลบค่าใน `FAILED` และ `LOCKED` ด้วย → ให้เขาตั้ง PIN ใหม่ตอนล็อกอิน

### บัญชีถูกล็อกเพราะใส่ PIN ผิดหลายครั้ง
ชีต `Users` → ล้างช่อง `LOCKED` และ `FAILED`

## 8. อาการเสียที่เจอบ่อย

| อาการ | สาเหตุที่เจอจริงมาแล้ว | แก้ |
|---|---|---|
| แก้ชีตแล้วหน้าจอไม่เปลี่ยน | แคช 5 นาที | รัน `clearCache()` |
| การ์ดเครื่องจักรว่างเปล่า ไม่มี error | ใส่ `PARAM_SHEET_ID` ผิดไฟล์ หรือชื่อเครื่องไม่ตรงทะเบียน | รัน `sourceAudit()` |
| ช่างล็อกอินแล้วไม่เห็นเครื่องของตัวเอง | ช่อง `ผู้ดูแล` ว่าง หรือสะกดไม่ตรง `STATIONS` | รัน `dataIssues()` |
| `No item with the given ID could be found` | สคริปต์มีสิทธิ์อ่านชีตแต่ไม่มีสิทธิ์**แก้ไขฟอร์ม** | ขอสิทธิ์แก้ไขฟอร์มนั้นให้บัญชีที่ deploy |
| `Exceeded maximum execution time` | งานเกิน 6 นาที | รันซ้ำ — ตัวสร้างฟอร์มลงทะเบียนก่อนสร้าง จึงข้ามของที่ทำไปแล้ว |
| เก็บรูปไม่ได้ | `DRIVE_FOLDER_ID` ผิด หรือบัญชีไม่มีสิทธิ์ในโฟลเดอร์ | ตรวจค่าใน Script Properties |
| หน้าเว็บขึ้นหน้าขออนุญาต | deployment ไม่ได้ตั้ง `ANYONE_ANONYMOUS` | ตรวจที่ Deploy › Manage deployments |

## 9. ข้อมูลลับ — อยู่ที่ไหน

**Project Settings › Script Properties** เท่านั้น · **ห้ามเก็บในชีต `ตั้งค่า`** ที่คนทั้งแผนกเปิดได้

| ชื่อ | คืออะไร |
|---|---|
| `SHEET_ID` | ไฟล์หลักของ CMMS |
| `DRIVE_FOLDER_ID` | โฟลเดอร์เก็บรูปที่แนบมากับใบแจ้งซ่อม |
| `AUTH_SECRET` | กุญแจเซ็น token — **เปลี่ยนเมื่อไหร่ ทุกคนหลุดล็อกอินทันที** |
| `DASHBOARD_PASSWORD` | รหัสเปิดหน้า Dashboard/Export |
| `PARAM_SHEET_ID` | ไฟล์พารามิเตอร์ของอีกโปรเจค — **อ่านอย่างเดียว** |
| `CHECK_SHEET_ID` | ไฟล์คำตอบเช็คชีตประจำวัน |

> วางลิงก์เต็มแทนรหัสได้ ระบบตัดให้เอง (`driveId_()`) แต่อ่านยากกว่า

## 10. สำรองข้อมูล

ยังไม่มีระบบอัตโนมัติ **ทำด้วยมืออย่างน้อยเดือนละครั้ง**

1. เปิดไฟล์ชีตหลัก → File › Make a copy → ตั้งชื่อ `CMMS backup YYYY-MM`
2. เก็บไว้ในโฟลเดอร์ของบริษัท ไม่ใช่ไดรฟ์ส่วนตัว
3. ทำกับไฟล์เช็คชีตและไฟล์พารามิเตอร์ด้วย

โค้ดสำรองอยู่ใน Apps Script เองแล้ว (ดูที่ `clasp versions`) และในโฟลเดอร์โปรเจคนี้
