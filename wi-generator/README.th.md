# โปรแกรมสร้างเอกสารสำหรับวิศวกรโรงงาน

[English](README.md) · **ไทย**

> ทำงานง่ายๆสไตล์วิศวกรโรงงานจอมขี้เกียจ

สร้างเอกสารมาตรฐานโรงงาน 16 ชนิดจบในไฟล์เดียว — **ดับเบิลคลิกเปิดในเบราว์เซอร์ได้เลย**
ไม่ต้องติดตั้ง Python ไม่ต้องลงโปรแกรม ไม่ต้องต่อเน็ต ไม่ต้องใช้เซิร์ฟเวอร์

ทุกอย่างทำงานในเครื่อง ข้อมูลไม่ออกไปไหน — แจกไฟล์เดียวให้เพื่อนร่วมงานใช้ได้ทันที

## เริ่มใช้งาน

โหลดไฟล์ `WI_Generator.html` ไฟล์เดียว แล้วเปิดด้วย Chrome หรือ Edge — จบ

```bash
git clone https://github.com/twnote05/Free-CMMS-For-poor-Engineer.git
cd Free-CMMS-For-poor-Engineer/wi-generator
```

(หรือกดปุ่มเขียว **Code → Download ZIP** บนหน้า GitHub ก็ได้)

## ปรับให้เป็นของบริษัทคุณ

ไฟล์นี้ตั้งค่าตั้งต้นไว้เป็นของโรงงานตัวอย่าง เอาไปใช้ได้เลยโดยไม่ต้องแก้อะไร
แต่ถ้าอยากให้เข้ากับโรงงานตัวเอง มีแค่ 3 จุด

**1. โลโก้กับไอคอน PPE — ไม่ต้องแก้โค้ด**
อัปโหลดจากหน้าโปรแกรมครั้งเดียว โปรแกรมจำไว้ให้ในเครื่อง ใช้ได้ทุกเอกสารหลังจากนั้น

**2. ค่าตั้งต้นในช่องกรอก — แก้ก้อน `CONFIG` ก้อนเดียว**
เปิด `WI_Generator.html` ด้วย Notepad หรือ VS Code ค้นหาคำว่า `const CONFIG` (อยู่ต้นไฟล์)

```js
const CONFIG = {
  fields: {
    docno:     'WI-MT-01',              // รหัสเอกสาร
    dept:      'ฝ่ายซ่อมบำรุง',            // แผนก/หน่วยงาน
    owner:     'ช่างเทคนิค/ซ่อมบำรุง',      // ผู้รับผิดชอบ
    purpose:   'เพื่อการใช้งานได้ถูกวิธี',   // วัตถุประสงค์
    worker:    'ช่างเทคนิค',               // ผู้ปฏิบัติ
    qpProcess: 'UV Coating',              // ชื่อ Process ของ Q-Point
  },
  positions: ['ช่างเทคนิค', 'หัวหน้างาน', 'วิศวกร', ...],   // ตำแหน่งในช่องผู้ลงนาม
  defaultPos: ['วิศวกร', 'รองผจก.โรงงาน', 'ผจก.โรงงาน'],   // ผู้จัดทำ/ผู้ทบทวน/ผู้อนุมัติ
};
```

แก้ข้อความในเครื่องหมาย `'...'` ให้เป็นของแผนกตัวเอง เซฟ แล้วเปิดใหม่ — เท่านั้น
ค่าพวกนี้เป็นแค่ค่าตั้งต้นที่เติมไว้ให้ ตอนใช้งานพิมพ์ทับได้ตลอด

**3. ตาราง Action Priority ของ FMEA — เฉพาะโรงงานที่ทำ FMEA**
ดูหมายเหตุในหัวข้อ "สูตรคำนวณที่ใช้" ด้านล่าง แก้ที่ตัวแปร `AP_TABLE`

> ไม่ต้องตั้งค่าอะไรอีก ไม่มีไฟล์ config แยก ไม่มี build step ไม่มี dependency ที่ต้องลง

## เอกสารที่สร้างได้

| กลุ่ม | เอกสาร |
|---|---|
| งานมาตรฐาน | WI (วิธีปฏิบัติงาน) · Q-Point · OPL · ป้ายความปลอดภัย · ผังงาน/VSM/Layout |
| วางแผนการผลิต | Routing Sheet · BOM · Time Study · Capacity · Line Balancing |
| คุณภาพ | Check Sheet · Control Chart X̄-R · FMEA |
| อื่น ๆ | SMED (ลดเวลาเปลี่ยนรุ่น) · ทะเบียนเครื่องมือ/Jig · Skill Matrix (OJT) |

## สิ่งที่โปรแกรมทำให้

- **จัดรูปและย่อขนาดให้เอง** อัปโหลดรูปตามลำดับขั้นตอน แล้วปล่อยให้โปรแกรมจัดลงช่อง
- **แบ่งหน้าและใส่เลขหน้า "หน้า x/y" ให้อัตโนมัติ** ทั้งบนจอ ตอนสั่งพิมพ์ และในไฟล์ Excel
- **คำนวณให้ครบ** ตามสูตรมาตรฐาน IE (ดูหัวข้อถัดไป)
- **พิมพ์ A4 / A3** ได้ทันที เอาไปแปะหน้างานได้เลย
- **Export Excel ได้ทุกชนิดเอกสาร** เป็นเซลล์จริงที่แก้ไขต่อได้ ไม่ใช่รูปภาพเอกสาร สำหรับให้ DCC เก็บต้นฉบับ
- **ดึงภาพจากวิดีโอ** ถ่ายคลิปตอนทำงานมา โปรแกรมตัดภาพช็อตสำคัญให้เลือก
- **แต่งรูปในตัว** ลูกศรชี้ กรอบแดง และเบลอปิดข้อมูลที่ไม่อยากให้เห็น
- **ใส่โลโก้บริษัท** ได้ทุกเอกสาร

## สูตรคำนวณที่ใช้

อ้างอิงมาตรฐานสากล ไม่ได้คิดเอาเอง

| เอกสาร | สูตรหลัก |
|---|---|
| Time Study | `NT = เวลาเฉลี่ย × Rating` · `ST = NT × (1 + Allowance)` · จำนวนรอบที่ต้องจับ `n = (z·s / (e·x̄))²` |
| Capacity | `กำลังผลิต = เวลาว่าง × 60 ÷ CT × จำนวนเครื่อง × ประสิทธิภาพ` · กำลังของสาย = จุดคอขวด |
| Line Balancing | `Takt = เวลาทำงาน ÷ ความต้องการ` · `E = งานรวม ÷ (คนรวม × รอบเวลาคอขวด)` (คิดจำนวนคนต่อสถานีด้วย) |
| BOM | `ต้องเบิก = ใช้จริง ÷ (1 − %ของเสีย)` ตามหลัก MRP |
| Control Chart | `UCL/LCL = X̄̄ ± A₂R̄` · `UCL_R = D₄R̄` · `Cp, Cpk` จาก `σ̂ = R̄/d₂` · กฎ Nelson ข้อ 2–8 |
| FMEA | `RPN = S × O × D` และ **Action Priority (AP)** ตาม AIAG-VDA ซึ่งให้น้ำหนัก S → O → D |
| SMED | เวลาเปลี่ยนรุ่นนับเฉพาะงาน **Internal** (ช่วงที่เครื่องหยุด) ตามหลัก SMED |

> **หมายเหตุเรื่องตาราง AP ของ FMEA** — ตารางฉบับจริงอยู่ในคู่มือ AIAG-VDA ที่มีลิขสิทธิ์
> และแหล่งเผยแพร่สาธารณะให้ตัวเลขไม่ตรงกัน ตารางในโปรแกรมเลือกฉบับที่สอดคล้องกันเองในตัว
> (เพิ่ม S/O/D แล้วความเร่งด่วนไม่ลดลง) **กรุณาเทียบกับคู่มือฉบับที่โรงงานถือครองก่อนใช้งานจริง**
> ถ้าต่างกันแก้ได้ที่ตัวแปร `AP_TABLE` จุดเดียวในไฟล์ HTML

## ตรวจสูตรก่อนเอาไปใช้

แก้สูตรในไฟล์ HTML เมื่อไหร่ ให้รันตัวตรวจซ้ำทุกครั้ง

```bash
node wi_test.js
```

ตรวจค่าที่คำนวณได้เทียบกับค่าที่คำนวณมือแยกไว้ รวมถึงตาราง Action Priority ครบทั้ง 1,000 ช่อง
(ถ้าอยากให้ตรวจส่วนสร้างไฟล์ Excel ด้วย ให้ `npm i exceljs` ก่อน — ไม่ลงก็รันได้ แค่ข้ามส่วนนั้นไป)

## โครงสร้างไฟล์

```
WI_Generator.html   โปรแกรมทั้งหมด (HTML + CSS + JS ในไฟล์เดียว)
wi_test.js          ตัวตรวจสูตรคำนวณ
```

ใช้ไลบรารีภายนอกตัวเดียวคือ **ExcelJS** โหลดจาก CDN เฉพาะตอนกดปุ่ม Export Excel
ส่วนที่เหลือเขียนเองทั้งหมด รวมถึงกราฟ (วาดด้วย SVG) และตัวแบ่งหน้า

## ข้อจำกัดที่ควรรู้

- ต้องเปิดด้วยเบราว์เซอร์รุ่นใหม่ (Chrome / Edge) — Internet Explorer ใช้ไม่ได้
- ตอนกด Export Excel ต้องต่อเน็ตครั้งแรกเพื่อโหลด ExcelJS จาก CDN
- ป้ายความปลอดภัยที่ Export เป็น Excel จะได้เป็น "ทะเบียนป้าย" สำหรับแก้ข้อความ
  ส่วนตัวป้ายที่เอาไปติดจริงให้สั่งพิมพ์จากหน้าเว็บ จะได้สัดส่วนตาม ISO 3864 ตรงกว่า
